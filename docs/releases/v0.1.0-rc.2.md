# Intuition Core v0.1.0-rc.2 operator guide

`v0.1.0-rc.2` is the first complete Intuition Core release candidate for
external operator trials. It contains the public API, atom services, workers,
chain ingestion, projections, and database migrations needed to build a local
knowledge graph or reconstruct one from Intuition testnet events.

This is a prerelease, not a production endorsement. Always select the explicit
tag or immutable digests below; the release did not publish `latest`.

## Before you start

Use Docker Engine or Docker Desktop with current Docker Compose v2. The
published override uses the Compose `!reset` merge tag and does not work with
legacy `docker-compose` v1. Bun 1.3 or newer is only needed for source-side
validation and the processing-scope dry run.

The tagged images are immutable, while this guide and its Compose
`WORKERS_PROCESSING_SCOPE` pass-through were added after the tag. Use the
current `main` operator files with the RC images:

```bash
git clone https://github.com/0xIntuition/intuition-core
cd intuition-core
cp example.env .env
export INTUITION_CORE_IMAGE_TAG=v0.1.0-rc.2
export COMPOSE_FILE=docker-compose.yml:docker-compose.published.yml
docker compose config -q
```

Do not put real provider secrets in shell history or commit them. Store them in
`.env`, keep that file untracked, and restrict its permissions:

```bash
chmod 600 .env
```

## Operator recipes

Recipes share one Compose project and its persistent volumes. Run
`docker compose down` before changing recipes so that services omitted by the
new recipe are stopped. Do not add `-v` unless you intend to erase local data.

### 1. Local knowledge graph and read API only

This starts PostgreSQL for the knowledge graph, applies its schema, and starts
the read API. It does not start TimescaleDB, Redis, chain ingestion,
projections, atom services, or processing workers.

```bash
docker compose up -d postgres-kg migrate api
docker compose ps
curl --fail --silent --show-error localhost:3000/health
curl --fail --silent --show-error localhost:3000/api/stats
curl --fail --silent --show-error localhost:3000/api/predicates
```

The default `API_AUTH=public-read` permits these reads. Writes require an API
key; see [Run your own node](../run-your-own-node.md#auth--api-keys).

### 2. Bounded testnet range

The deterministic 500-block window below is the verified, inexpensive
end-to-end indexing recipe:

```bash
docker compose down
export INTUITION_RPC_URL=https://testnet.rpc.intuition.systems/http
export CHAIN_ID=13579
export MULTIVAULT_CONTRACT_ADDRESS=0xeBc49d356B7f64D888130D85CC6D17114a6843ec
export MULTIVAULT_START_BLOCK=9030416
export MULTIVAULT_END_BLOCK=9030916
docker compose --profile indexing up -d
docker compose --profile indexing ps -a
curl --fail --silent --show-error localhost:3000/health
curl --fail --silent --show-error localhost:3000/api/stats
curl --fail --silent --show-error localhost:9091/metrics
curl --fail --silent --show-error localhost:9092/health/live
```

The indexer exits successfully after a bounded range; that is expected. For the
full automated assertion and cleanup, use:

```bash
make smoke-index-published IMAGE_TAG=v0.1.0-rc.2
```

The published-image verification indexed exactly `201` canonical events,
advanced `21` projection checkpoints, caught `core_entities` up to `50/50`, and
returned `50` atoms through the API.

### 3. Full index to chain head

Full indexing uses the same required chain settings but leaves the end block
empty. Size storage and RPC capacity for the complete history before starting:

```bash
docker compose down
export INTUITION_RPC_URL=https://testnet.rpc.intuition.systems/http
export CHAIN_ID=13579
export MULTIVAULT_CONTRACT_ADDRESS=0xeBc49d356B7f64D888130D85CC6D17114a6843ec
export MULTIVAULT_START_BLOCK=9030416
export MULTIVAULT_END_BLOCK=
docker compose --profile indexing up -d
docker compose --profile indexing ps
curl --fail --silent --show-error localhost:9091/metrics
curl --fail --silent --show-error localhost:9092/health/live
```

Unlike the bounded recipe, the indexer remains running and follows chain head.
Restarting is safe: ingestion and projections resume from persisted state and
projection checkpoints.

### 4. Parse and classify without enrichment

This starts only the KG, API, parse worker, and classification worker. It omits
the enrichment worker and stateless atom-services process:

```bash
docker compose down
docker compose up -d api workers-parse workers-classification
docker compose ps
curl --fail --silent --show-error localhost:3000/health
curl --fail --silent --show-error localhost:4110/healthz
curl --fail --silent --show-error localhost:4112/healthz
```

New atoms can finish parsing and classification, but they will not reach a
completed enrichment stage until `workers-enrichment` is started. Existing
enrichment artifacts remain in the database.

### 5. Rich enrichment with provider keys

Keyless providers work without configuration. Add only the providers you need
to `.env`; never commit real values:

```dotenv
SPOTIFY_CLIENT_ID=replace-with-your-client-id
SPOTIFY_CLIENT_SECRET=replace-with-your-client-secret
GITHUB_TOKEN=replace-with-your-token
PODCAST_INDEX_API_KEY=replace-with-your-key
PODCAST_INDEX_API_SECRET=replace-with-your-secret
```

Then recreate the stateless service and complete worker pipeline:

```bash
chmod 600 .env
docker compose up -d --force-recreate atom-services workers-parse workers-classification workers-enrichment
curl --fail --silent --show-error localhost:4010/health
docker compose logs --tail=100 atom-services workers-enrichment
```

Provider failures are fail-soft: one unavailable or unconfigured provider does
not fail the complete pipeline. See
[Enrichment providers](../enrichment-providers.md) for provider-specific setup.

### 6. Music and podcast processing preview

First validate the bundled scope config from the current source tree:

```bash
bun install --frozen-lockfile
make scope-dry-run SCOPE_CONFIG=docs/indexing-scope.example.json
```

Then select the combined worker preset and recreate all worker modes:

```bash
docker compose down
export WORKERS_PROCESSING_SCOPE=music-and-podcasts
docker compose up -d workers-parse workers-classification workers-enrichment
docker compose exec workers-enrichment printenv WORKERS_PROCESSING_SCOPE
```

The final command must print `music-and-podcasts`. This preview deliberately
keeps parsing and classification broad and gates only enrichment after
classification. Matching rows use the music/podcast provider allowlist;
non-matching rows are marked `enrichment_status=skipped`. It does not delete
existing artifacts, requeue rows when the scope changes, or filter API reads.
See [Indexing scope configuration](../indexing-scope-config.md#worker-prototype-notes)
for the exact prototype boundary.

## Configuration and migration impact

- No schema or migration changes were introduced between the tagged source and
  the release images. The one-shot `migrate` and `timescale-migrate` services
  remain idempotent.
- Chain indexing requires `INTUITION_RPC_URL`, `CHAIN_ID`,
  `MULTIVAULT_CONTRACT_ADDRESS`, and `MULTIVAULT_START_BLOCK` at container
  runtime. `MULTIVAULT_END_BLOCK` is optional.
- Core is Postgres-only. Leave `SURREAL_DB_URL` empty; the projection service
  uses its no-op graph sink while `core_entities` writes to PostgreSQL.
- Product analytics and market-schema dual writes remain disabled by the
  default `DISABLED_PROJECTIONS` value.
- The API defaults to `public-read`: reads are open and writes require a key.
- `WORKERS_PROCESSING_SCOPE` defaults to `full`. The current Compose operator
  files pass it to every worker; the RC worker image already implements all four
  accepted values.

## Common failures

| Symptom | What to check |
| --- | --- |
| Compose rejects `!reset` or ignores the published override | Use current Docker Compose v2, set `COMPOSE_FILE=docker-compose.yml:docker-compose.published.yml`, and run `docker compose config -q`. |
| Compose reports that `INTUITION_CORE_IMAGE_TAG` is required | Export `INTUITION_CORE_IMAGE_TAG=v0.1.0-rc.2`, or export all six digest-reference variables. There is no `latest` fallback. |
| Indexer panics because `CHAIN_ID` or another chain variable is missing | Put all four required variables in `.env` or export them before `docker compose up`; they must reach the container runtime. |
| `event_store` remains empty | Confirm the contract address and block window, then inspect `localhost:9091/metrics`. The verified window is `9030416-9030916`. |
| Indexer shows `Exited (0)` | Normal for a bounded `MULTIVAULT_END_BLOCK`. Only a nonzero exit is a failure. |
| API writes return `401 api_key_required` | `public-read` is the default. Mint a key as documented, or use `API_AUTH=open` only for disposable loopback experiments. |
| Projection output lags ingestion | Check `localhost:9092/health/live`, projection logs, and TimescaleDB health. Checkpoints persist and resume after restart. |
| Enrichment reports `skipped` | Normal for non-applicable atoms and providers whose optional keys are absent. |
| Port `3000`, `4010`, `4110`, `4111`, `4112`, `9091`, or `9092` is occupied | Stop the conflicting process. `API_HOST_PORT` and `ATOM_SERVICES_HOST_PORT` can remap the first two; worker and metrics ports are currently fixed in Compose. |
| Rust services reject PostgreSQL `TimeZone=UTC` | A partially extracted Timescale image can have corrupt zoneinfo. Follow the image re-pull procedure in [Troubleshooting](../troubleshooting.md#invalid-value-for-parameter-timezone-utc-from-postgres). |
| You find `v0.1.0-rc.1` instructions or images | Do not use them. RC.1 was incomplete; RC.2 supersedes it. |

For logs and a non-destructive stop:

```bash
docker compose --profile indexing logs --tail=200
docker compose --profile indexing down
```

Volumes survive `down`. `docker compose down -v` permanently deletes the local
KG, event store, Redis data, and other Compose volumes.

## Known limitations and deferred work

- This is a release candidate. It has no stable-release compatibility promise,
  production support SLA, or automatic `latest` tag.
- There is no GitHub Release object for this tag. Creating one after publication
  would retrigger the image workflow, so this versioned document records the
  release notes without risking movement of verified tags.
- Full-history duration, storage use, and RPC load depend on chain growth and
  provider capacity; the bounded smoke result is not a full-sync benchmark.
- Product analytics projections and dual-write migration paths remain disabled
  in the public default.
- The devnet deployer is source-built and local-only.
- Service crates and private workspace packages are not registry artifacts;
  their supported distribution is the six public container images.
- Processing scope is an enrichment preview. Requeue/backfill behavior,
  cleanup of out-of-scope artifacts, and API domain filters are intentionally
  deferred.
- The multi-platform ingestion image is functionally verified, but its emulated
  `linux/arm64` release build is slow in hosted CI. This is a release-build
  performance concern, not a known ingestion runtime defect.

## Rollback

Stop the stack, select an earlier known-good tag or all matching immutable
digests, validate the rendered configuration, and restart. Do not retag or move
`v0.1.0-rc.2`.

```bash
docker compose --profile indexing down
export INTUITION_CORE_IMAGE_TAG=replace-with-known-good-tag
docker compose config -q
docker compose --profile indexing up -d
```

Before rolling back across a future schema change, consult that release's
migration notes and take database backups. RC.2 itself adds no new migration.
